Safe active checks

Staging checks with guard rails.

Active checks send real requests, so they're the part of Fortis we restrict most. Every check needs all of these in place first.

  1. A signed testing authorisationYour organisation authorises Fortis to test named targets, in writing, before anything runs.
  2. DNS ownership proofA TXT record on the target domain. Change it and checks stop.
  3. Staging onlyTargets flagged as production are refused. Production is observed, never actively tested.
  4. Your own test usersChecks sign in as test accounts you create, with test data only.
  5. Read-only by defaultWrite checks are opt-in, per route, and rate-limited.
  6. Kill switchPause all checks for a target instantly from the dashboard or CLI.
